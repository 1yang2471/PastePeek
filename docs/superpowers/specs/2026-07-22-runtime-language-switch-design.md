# PastePeek 运行时语言切换设计

日期：2026-07-22  
状态：待用户审阅

## 目标

在同一个 PastePeek 程序中提供简体中文和英文运行时界面。默认保持简体中文，用户可从 HUD 或系统托盘切换到英文；切换结果写入现有本地配置，重启后继续生效。

## 非目标

- 不维护两套业务逻辑、两份 EXE 或两套发布流程。
- 不翻译用户剪贴板正文、HTML、Markdown、代码或链接参数。
- 不改变剪贴板读取、序列校验、主动操作、回滚和安全拒绝策略。
- 不引入网络翻译、云服务、账户或剪贴板历史。

## 方案比较

### 方案 A：单一 EXE + 运行时语言切换（采用）

新增轻量本地化模块，所有由 PastePeek 生成的 UI、预测、预览和操作反馈都根据当前语言取文案；配置仍使用现有 `config.json`。优点是发布物和业务逻辑只有一份，用户可即时切换，默认中文用户不受影响。

### 方案 B：两份独立 EXE

为中文和英文分别构建入口和资源。它会重复发布、测试和版本同步工作，也无法满足用户在同一安装目录内切换语言的便利性，因此不采用。

### 方案 C：仅翻译静态 UI

只替换按钮和菜单，预测矩阵、预览清单和主动操作反馈仍为中文。实现成本低，但英文模式不完整，违背“运行时 HUD 和托盘文案也要英文”的目标，因此不采用。

## 架构

### 本地化模块

新增 `src/i18n.py`，集中定义：

- 支持语言：`zh-CN`、`en-US`；默认语言：`zh-CN`。
- 非法、缺失或错误类型的语言值统一回退到默认语言。
- HUD、托盘、风险、内容类型、目标应用、主动操作和预览结构标签的静态文案。
- 文案格式化只接收结构化参数，不拼接未经验证的用户输入到 HTML 标签或命令。

### 配置

`HudWindow._load_config()` 增加 `language` 默认字段并做白名单归一化。`_save_state()` 保留该字段；旧配置缺少该字段时继续使用简体中文。配置写入失败仍不得阻塞 UI。

### 运行时数据流

```text
HUD/托盘语言菜单
        |
        v
HudWindow.set_language() -- 保存 config.json、刷新静态控件
        |
        +--> PastePeekApp.set_language()
        |       |
        |       +--> OutcomePredictor.generate(language)
        |       +--> PreviewRenderer.render(language)
        |       +--> text_toolkit 操作反馈(language)
        |
        +--> TrayController.set_language()
                |
                +--> 重建/刷新托盘菜单、语言勾选状态和错误提示
```

语言变化不得清空或改写剪贴板。若当前存在剪贴板快照，应用只基于内存快照重新生成 `AppOutput` 并发出已有的 `analysis_ready` 信号；若没有快照，只刷新静态控件。

### HUD

- HUD“更多”菜单保留目标选择，并增加语言子菜单；当前语言使用可见勾选状态。
- 目标图标按钮、tooltip、风险标签、首运行提示、主动操作按钮、无操作提示、错误/成功反馈全部从本地化模块取值。
- 语言切换后立即刷新当前 `AppOutput`，包括预测结论、原因、建议、风险清单和预览结构标签。
- 保持原有尺寸约束；英文较长文案通过现有换行和高度计算处理，不改变交互快捷键。

### 托盘

- 托盘菜单增加语言子菜单；显示/隐藏、开机启动、退出和启动失败提示随语言刷新。
- 菜单刷新保持幂等，不重复连接信号，不改变托盘显隐和开机启动行为。

### 预测、预览和主动操作

- `OutcomePredictor` 根据语言选择同一 `(content_type, target)` 矩阵的中文或英文文案，风险级别和动作 key 保持不变。
- `PreviewRenderer` 接收语言参数，只翻译由渲染器生成的标题、清单标签、空内容提示和默认风险；剪贴板原文保持原样并继续经过现有安全 HTML 净化。
- `PastePeekApp` 的非文本说明、动作前置拒绝和版本校验提示根据语言返回。
- `text_toolkit` 的 `clean_url`、`strip_formats`、`merge_lines` 新增可选语言参数，默认中文，所有成功、失败、回滚和拒绝消息保持现有安全语义。

## 错误处理

- 无效语言值：静默回退 `zh-CN`，不阻止启动。
- 本地化键缺失：使用同语言的安全通用文案；不得把内部 key 或异常堆栈展示给用户。
- 配置读取/写入失败：继续使用当前语言或默认中文；不影响剪贴板监听和托盘生命周期。
- 英文文案导致布局变高：沿用现有固定宽度、自动换行和屏幕边界校正；不允许覆盖控件或把 HUD 推出可用工作区。

## 测试策略

先按 TDD 逐纵切片：

1. 本地化模块：支持语言、非法值回退、静态文案和格式化参数。
2. 配置：默认中文、旧配置兼容、英文保存/读取和非法值回退。
3. 预测与预览：英文矩阵覆盖四类内容和所有目标；生成的 PastePeek 文案不含中文，用户正文仍保留。
4. HUD：英文静态控件、目标菜单、语言菜单、当前结果即时刷新和错误/成功反馈。
5. 托盘：英文菜单、语言勾选状态、显示/隐藏和启动失败提示。
6. 主动操作：英文成功/拒绝/序列变化消息；剪贴板安全回归仍通过。
7. 全量回归：现有中文断言、GUI 几何、单实例、托盘、剪贴板安全和发布工程测试全部保持通过。

验收标准：默认启动仍为中文；切换到英文后 HUD 和托盘不再显示 PastePeek 自己生成的中文；重启后保持英文；切换期间剪贴板内容、格式、序列保护和安全拒绝行为不变。

## 版本与发布

功能完成后作为已有 `v2.0.0-rc.2` 之后的新版本发布，建议版本为 `v2.0.0-rc.3`。不覆盖旧标签；发布前重新运行全量测试、Ruff、compileall、构建和 GUI/托盘验收。
